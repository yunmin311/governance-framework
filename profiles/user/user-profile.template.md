# 用户工作系统 · 模板（换成你自己的）

> 这份 Profile 记录**你**在真实项目里反复验证过的工作习惯、判断方式和协作偏好。它跨项目复用，但不是普遍适用于所有人的法律。
> 优先级：你的当前决定 > 本 Profile > 项目唯一正本（项目可写得更具体，但不能把项目专属事实反向升级为全局习惯）。
> **用法**：逐节删掉占位、填你自己的答案；填不出的节先留空并标 `TODO`，别硬编。

## 1. 你的真实角色

- 你首先是：____（例：设计师 / 产品方向决定者 / 研究者 / 工程负责人）。
- 你**不是**：____（列出你拒绝承担的角色，例：AI 之间的人工传声筒；每次提交后的默认测试员；AI 断线时的备用程序员；替 AI 找文件/复制命令的人）。
- 因此，在工具和权限允许时，AI 应主动____（读取事实 / 完成修改 / 执行验证 / 提交推送），只有____（目标 / 方向 / 审美 / 不可逆动作 / 真实花钱 / 外部发布）才需要你本人。

## 2. 事实自取，你只传方向和拍板

- 哪些事实 AI 必须自己从仓库、正本、台账、测试读取，不要求你复述？____
- 收到别的对话的汇报时，AI 先做的三件事：找到真实来源 / 区分已完成·进行中·候选·计划·未知 / 判断哪些真的需要你。

## 3. 流程轻重跟什么走

- 小而可回滚、地盘清楚、不改结构的任务：____（可否报计划后连续做完？）
- 必须立 Spec / 任务包 + 门禁的任务：____（跨模块 / 改数据结构 / 外部付费 / 改长期设计 / 影响多角色）。
- 无论大小都不能省的刹车：所有权、唯一正本、显式 Git 路径、独立验证、批准人、回滚点。

## 4. 设计工作（有设计项目才填）

- 每个设计项目至少要有：冻结的当前设计基线 / 可复用的设计方法或 Skill / 决策记录。缺一只能产出探索稿。
- 你的素材与参考怎么管理？____（如：素材库只由某个角色写；水只从库流向项目、只复制不引用；public/private 分层）。

## 5. 报告与转发怎么给你

- 报告格式默认：____（例：Markdown；只有关系树/权责/视觉对照才用 HTML）。
- 一份合格报告必须分开：已验证完成 / 已完成待验证 / 进行中 / 候选建议 / 阻塞或未知 / 只有你能决定。
- “只有你能做的”只放真需要你的事，每项给选择+后果+推荐；AI 能自己跑的命令、能读的文件、能修的问题不许放进去。
- 转发给其他对话用完整块：核验后的总结 + 要做什么 + 建议 + 可直接发送的提示词；不预填你没拍板的决定。

## 6. 文件落位与交付

- AI 开工前先声明 `output_root`、正本产物、临时产物、命名、Review 位置、清理策略。
- 你接收的交付必须能本机打开、给绝对路径与正本关系；不堆桌面、不只给外部链接、不散在奇怪目录。

## 7. AI 负责到哪里 / 何时必须停

- 权限、风险、所有权允许时，AI 负责：读取、修改、测试、渲染、检查、回执、显式提交、推送、验证远端。
- AI 必须停下：需要删除或不可逆覆盖 / 历史改写 / 公开私密材料 / 改系统硬权限 / 来源冲突无法用证据解决 / 缺少会改变结果的你的决定。

## 8. 多电脑与同步（有多台机才填）

- 本机/其它机的分工：____。同步通道：____（如 GitHub，做完活的机器推、另一台先拉，永不双写）。
- 涉密/公司材料策略：____（如：永不进个人同步）。
- 换机时带走治理内核、用户 Profile、模板、Skill、适配方法；机器路径、花名册、已装能力、硬权限状态必须重新发现，不照抄旧机。
