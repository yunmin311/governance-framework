============================================================
只读 Diff 复杂度审查
============================================================

只读取当前 Git Diff 和少量直接上下文。不要扫描整个仓库，不要打开无关文件。

只检查以下“过度工程化”信号，其余一律不管：
1. 是否引入无必要复杂度；
2. 是否重复实现项目已有能力；
3. 是否可以改用标准库或平台原生能力；
4. 是否增加推测性抽象（为“将来可能”而不是当前需要）；
5. 是否出现单实现接口、无价值包装层、或不必要的新依赖。

硬约束：
- 不修改任何文件；不运行 commit / push；不做删除或移动。
- 不检查正确性、安全性、性能或视觉质量（那是别的门禁的事）。
- 不得削弱已批准 Spec、项目架构、契约、测试、安全和数据保护——发现与它们冲突时，以受保护约束优先，把你的建议降为“仅供参考”。
- 所有发现只标 CANDIDATE，交由对应角色和用户决定，不自行落地。

每条发现按此格式输出：
  Location:              （文件:行 或 Diff 片段）
  Evidence:              （为什么算过度复杂，引 Diff 证据）
  Candidate simplification: （更简做法，标 CANDIDATE）
  Protected constraints: （涉及的已批准 Spec/架构/测试/安全，不得削弱）
  Risk:                  （采纳该简化的风险）

没有可靠发现时，只输出一行：
  Lean enough. No change recommended.

============================================================
边界提醒
============================================================
本能力只是“审查视角”，无权决定功能范围、架构、删除或 Git 操作。
Pilot 只在治理系统 v2.2.1 通过后，用三个真实 Diff 单独评估，不影响版本通过。
