# 对话开工声明卡 v2

每个长期角色和重要临时任务在动手前填写。声明的目标是把权限区、正本、共享写入面和交付位置提前说清楚，不是收尾补手续。

## 可复制模板

```text
【对话开工声明 v2】
- task_mode：QUICK / NORMAL / STRUCTURAL / INCIDENT
- write_capability：READ-ONLY / WRITE / APPROVAL_REQUIRED
- 项目：
- 当前角色/代班角色：
- governance_root：
- machine_profile：
- project_adapter：
- 项目唯一正本（实际已读路径 + 版本/提交）：
- 当前设计基线/专业 Skill（不适用写 N/A）：

- resolved_project_root：
- read_scope：
- create_scope：
- modify_scope：
- forbidden_scope：
- shared_write_surfaces：

- output_root：
- canonical_outputs：
- temporary_outputs：
- final_review_path：

- lifecycle / execution / verification / incident：
- Driver / Approver / Contributors / Informed：
- Git 所有者、允许命令与显式路径：
- 风险级别：低风险可回滚 / 高风险需门禁
- 计划执行、验证、提交、推送与回滚：
- 当前 UNKNOWN / 冲突：
```

## 开工检查

- 路径已经在当前机器重解析，不照抄旧盘符。
- 声称已读的文件确实可达，并记录版本或提交。
- `modify_scope` 具体到文件或目录，不写“项目全部”。
- 正本和临时产物分开；临时产物只有在这里声明后才允许按规则清理。
- 共享工作树、Git index、共享记忆或台账已经识别所有者。
- 设计工作已经读当前基线和方法 Skill；否则只做探索。
- 批准人只负责该道门，不把所有批准权默认给总管。

## 收尾要求

最终 Review 必须列：读了什么，建/改/移了什么，没有删除什么，每个产物的准确路径、状态和正本关系，验证证据，Git/远端状态，未知项和回滚点。不能只说“已生成”或让用户自己找链接。
