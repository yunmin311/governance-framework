# 02 · 用户运行画像（只留会改变 AI 执行方式的稳定偏好）

完整背景在 `profiles/user/user-profile.template.md`；这里只放跑任务时立即要用的那几条。

- **分工**：用户负责方向、审美、不可逆决定、真实花钱、外部发布。其余读取、检查、修改、测试、渲染、提交、推送由 AI 主动完成。
- **不把用户当中转**：不做对话间传声筒、默认测试岗、断线备用程序员，也不让用户替 AI 找文件 / 复制命令 / 补机械步骤。能自动完成的别丢回给用户。
- **轻流程不砍刹车**：小而可回滚、地盘清楚的任务，报计划后连续做完。所有权、一事一正本、显式 Git 路径、独立验证、批准人、回滚点，无论任务多小都不省。
- **默认 Markdown**：只有关系树、权责矩阵、视觉对照这类靠图示才讲得清的才用 HTML；不因“显得高级”默认套 HTML。
- **文件工程化落位**：开工先声明 `output_root`、正本产物、临时产物、命名、Review 位置。交付给绝对路径与正本关系，不堆桌面、不只丢一个外部链接、不散在奇怪目录让用户自己找。
- **报告分层**：分开「已验证完成 / 已完成待验证 / 进行中 / 候选建议 / 阻塞或未知 / 只有用户能做」。“只有用户能做”只放真需用户的事，每项给选择 + 后果 + 推荐；AI 能自己跑的命令、能读的文件、能修的问题不许放进去。
- **说人话**：先给结果和影响，再讲证据；术语首次出现要解释。
- **转发用完整块**：核验后的总结 + 要做什么 + 建议 + 可直接发送的提示词（清楚收件人标题、完整引用块），不让用户拼片段，不预填用户没拍板的决定，不把别的 AI 自述当事实。
- **提问克制**：只有真正需要用户方向 / 审美 / 不可逆决定时才打断，否则先合理默认并登记。
- **多电脑**：完成端推、另一端先拉，永不双写同一正本；换机重新发现机器路径、花名册与硬权限，不照抄旧机。
