# 周期复盘(周 / 月 / 自定义区间)

节奏:每周一次、每月一次,或用户说"复盘一下 / 总结这段时间 / 我要汇报"。大会话后可做一次轻量"就地沉淀"。周和月走同一套步骤,只是区间和详略不同。

## 第 0 步 · 先定三件事

1. **区间**:从哪天到哪天(默认:上次复盘至今;用户说"这一个月"就按整月)。
2. **读者**:自己 / 上级 / 他人——决定交付形态(SKILL §4 的 A/B/C,可并行出多份)。
3. **要不要图**:要,就照 `visual-records.md` 基准线出自阅版 html。

## 步骤

1. **取证(先数字后记忆,SKILL §3)**:逐仓 git 实数 → 会话统计 → 交付物实地清点 → 记忆只当索引。区间内每个项目都要碰到,包括参与的公司项目和小工具仓;漏项是用户最先发现的问题。
2. **综合**(Generative Agents 式反思):聚类,找出——反复出现的偏好、反复踩的坑、成长点、以及跟现画像矛盾的地方。
3. **提议三样**:
   - **画像 delta**:值得升为 L3 稳定模式的新偏好(需重复出现,非单次);提议时用人话讲清"批了会改变什么行为"。
   - **skill 候选**:某套打法已被真实任务验证、可复用 → 提议蒸馏(交专职蒸馏流程 / 用户批准)。
   - **该删的糟粕**:过期、已被推翻、噪音的记忆 → 提议删 / 归档。**删之前逐条审一遍原文**:里面可能藏着别处没记的活信息(路径、配置、还没办的事),先抢救进对应正本再删。
4. **多轮 clarify**:跟用户逐条确认,取精华去糟粕;有分歧就问,不自作主张。**汇报类交付默认多轮打磨**:v1 是草稿,逐轮吃反馈(口径、详略、语气、遗漏),版本留档 v1/v2/…,用户说定稿才停。
5. **批准后写入**:用户批准的 delta 才写进 L3 画像 + 记忆;被否的记一句"考虑过、否决",别下周又冒出来。

## 报告格式

默认用用户的语言。三种形态的硬规矩在 SKILL §4;这里只强调对外版(B)最容易犯的错:

- 拿记忆当现状(状态类事实必须实测);
- 漏掉参与类项目和进行中的项目;
- 修辞表演:比喻、套话、自我评价、排比——用户原话"味道太恶心了",一律不许;
- 一稿定稿的幻想:准备好被砸三轮以上。

## 反模式

- 别拿一周波动当习惯(单次过拟合)——要重复出现。
- 别把画像堆大(lost in the middle)——只放稳定的,细节留原子。
- 有反证就撤销已学的模式(反确认偏误)。
- 别拿旧盘点当现状——先实测再写。
