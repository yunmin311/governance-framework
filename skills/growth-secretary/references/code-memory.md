# 代码记忆子模式

**只在代码相关任务启用**(改代码、读代码、调 bug、设计接口时),不污染日常记忆。

## 直接用(照搬)
- 把**代码决定**(选型、架构取舍)、**踩坑**(反复失败的修法)、**约定**(命名、风格、目录)落成 L1 原子;项目级的写进项目正本(CLAUDE.md / AGENTS.md),别只留在聊天里。
- 一事一档、带 `#code` 标签 + `[[链接]]`,方便召回。

## 借思想(Code-Graph,轻量版)
腾讯 Code-Graph 索引“符号 / 文件 / 调用关系 / 影响路径”,做改动前的影响分析。我们不上整套图数据库,取其思想:
- 改一处代码前,记一条轻量**“影响笔记”原子**:这次动了哪些符号 / 文件、谁调用它、可能波及哪里。
- 用途:下次改同一处,先召回这条影响笔记,少踩回归坑。

## 边界
- 不跑外部服务、不引向量库;保持纯文件 + 零依赖。
- 代码记忆同样服从治理:重要约定进项目正本要按项目 adapter 的提交岗;跨项目影响升级模式。
