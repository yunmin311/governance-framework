# 记忆模型 · 四层 + 文件布局 + 跨模型同步

## 四层(L0 → L3,递进沉淀)
- **L0 对话**:原始交互全文。用途:核对原话、时间、来源。不长期堆,过期归档。
- **L1 原子**:抽出的事实 / 偏好 / 约束 / 事件,一事一档。用途:精确召回可执行信息。= 我们现有的记忆档。
- **L2 场景**:按项目 / 主题组织的知识块。用途:快速恢复某项目的工作上下文。对应 `topics/` + 项目正本。
- **L3 人格**:用户画像,长期稳定的偏好与模式。用途:让任何 agent 快速进入你的上下文。= 用户画像层(可移植)。

**沉淀**:异步 / 周期地把 L0 → L1 → L2 → L3 提炼(见 `weekly-review.md`)。
**召回**:先用 L2/L3 快速起步;要具体时再下探 L1/L0,按条数 / 字符预算 / 超时封顶。

## 文件布局(仿 agentmemory,纯 markdown)
```
<memory-root>/
  MEMORY.md            # 索引:一行一条,指向原子档
  <原子档>             # L1:一事一档(frontmatter + 正文 + [[链接]] + #标签)
  daily/2026-08-06.md  # 追加式日志
  topics/<主题>.md     # L2 场景 / 主题
```
约定:`#decision` `#preference` 等标签 + `[[wiki 链接]]` 作为内容约定,方便关键词 / 语义召回。无数据库、无云、git 友好。

## 中立位置 + 跨账号 / 跨模型同步
- **中立位置**:记忆不放在任何单一模型的私有记忆里(如某家的 memory 服务),放一个各 agent 都能读写的**中立目录**(建议在用户私有实例仓内的 `memory/`)。
- **各 agent 各装薄 skill**:Claude / Codex / 其它 agent 各装一份**指向同一记忆目录**的 skill(仿 agentmemory 把 skill 装进各家 config、指向同一份记忆)。
- **同步通道**:私有仓 push/pull,单写者、做完活的机器推、另一台先拉、永不双写(沿用体系两仓)。
- **底线**:换账号、换模型,**最基础的记忆(L1 原子 + L3 画像)必须还在**。

## 召回预算(防 lost-in-middle)
默认只注入必要的:优先未决事项、相关主题、当日日志、画像;设字符上限;其余按需召回。别一股脑通读整个记忆库。
