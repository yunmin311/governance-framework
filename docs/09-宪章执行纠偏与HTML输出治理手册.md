# 宪章执行纠偏与 HTML 输出治理手册

**目的：** 当 AI 开始幻觉、绕过宪章、忘记设计基线，或输出 HTML 出现“前面精致、后面敷衍”时，让用户能快速判断严重程度、立即止损，并把结果恢复到可验证状态。

---

## 1. 先区分四种问题

| 问题 | 表现 | 默认处置 |
|---|---|---|
| 局部缺陷 | 单个间距、文案、组件或断点有误 | C1 `CORRECT-IN-PLACE` |
| 系统漂移 | 多个模块逐渐偏离同一基线，后半段质量下降 | C2 `BASELINE-RESET` |
| 证据幻觉 | 声称读取了未读取的文件、链接、截图或对话 | C3 `INCIDENT(READ-ONLY)` |
| 权限绕过 | 未经批准改方向、覆盖正本、宣布批准或冻结 | C3 `INCIDENT(READ-ONLY)` |

“我觉得不太对”可以启动检查，但不能直接当成根因。先让 AI 说出它实际读取了什么、引用哪个版本、改了哪些文件、验证了什么。

## 2. 三条不可协商的规则

1. **技术正确不等于设计正确。** HTML 能打开、组件能点击、构建能通过，仍可能不符合艺术方向。
2. **自检不等于批准。** 同一个对话可以检查自己的输出，但不能因此把 `EXPLORE` 提升为 `APPROVED/FROZEN`。
3. **继续生成不等于解决问题。** 发现系统漂移后必须停止扩写；不能用更多代码覆盖错误基线。

## 3. 一分钟诊断

当你发现结果“不像以前”“前面好、后面随便”“它好像忘了”时，先要求对话只回答以下内容，不允许继续改文件：

```text
当前任务：
当前角色：
运行模式：
实际读取的项目正本：
实际读取的设计基线及版本：
实际读取的当前任务或 Spec：
本轮创建或修改的文件：
已经实际渲染或打开检查的范围：
无法验证的内容：
与基线已知的差异：
你建议的纠偏等级：C1 / C2 / C3
建议依据：
```

以下任一项回答不出来，不允许用“根据上下文”“按照之前的风格”“应该是”补齐。缺少来源时至少进入 C2；虚构来源或权限越界时直接进入 C3。

## 4. C1：`CORRECT-IN-PLACE`

### 4.1 适用条件

- 当前项目正本和设计基线明确。
- 错误范围可以准确点名。
- 未出错区域仍符合基线。
- 修正不改变整体艺术方向、信息架构或文件正本。

### 4.2 强制动作

1. 明确冻结未出错区域。
2. 列出允许修改的页面、模块、选择器或文件。
3. 只修点名问题。
4. 比较修改前后差异。
5. 复查受影响区域和相邻区域。
6. 输出 C1 回执。

### 4.3 禁止动作

- 不顺手重构无关组件。
- 不更换字体、色阶、圆角、内容密度或整体版式。
- 不把局部修复包装成“全面升级”。
- 不以缩小截图范围隐藏其他问题。

### 4.4 退出条件

指定问题消失；未授权区域没有非预期变化；实际渲染或打开检查完成。无法验证视觉结果时标记 `UNVERIFIED`，不能宣称完成。

## 5. C2：`BASELINE-RESET`

### 5.1 适用条件

- 首屏精致，尾部模块明显简化或退化。
- 不同页面使用了不同字体、颜色、间距、圆角或组件语言。
- 页面结构大体正确，但整体气质偏离冻结方向。
- 多次局部补丁仍不断出现新偏差。
- 对话无法清楚说明当前设计基线，但没有虚构读取证据。

### 5.2 强制动作

1. 停止继续添加页面和模块。
2. 保存当前产物为 `CANDIDATE` 或 `QUARANTINED`，不覆盖可信正本。
3. 重新读取项目正本、设计基线、参考分析、组件规则、被否决方向和当前任务。
4. 建立完整页面与模块覆盖表，包括尾部、空状态、错误状态和响应式状态。
5. 对每一项标记 `KEEP / REPAIR / REBUILD / UNKNOWN`。
6. 只保留有证据符合基线的部分，修复或重做其余部分。
7. 重新渲染全部目标范围并提交 C2 回执。

### 5.3 禁止动作

- 不只修首屏或用户刚指出的截图。
- 不用“统一加一个颜色”“统一换一种字体”代替系统分析。
- 不重新发明艺术方向。
- 不把旧产物删除到无法比较。

### 5.4 退出条件

全部目标页面和模块都有覆盖记录；关键 Token 与组件规则一致；尾部质量不低于首屏；渲染验收通过；仍未确认的艺术判断交给用户。

## 6. C3：`INCIDENT(READ-ONLY)`

### 6.1 立即触发条件

- 声称读取了实际无法访问的文件、对话、网页或应用。
- 无法提供基线来源，却把新设计称为既定方案。
- 未经授权解除冻结、改变方向、覆盖正本或删除文件。
- 把 `EXPLORE/CANDIDATE` 说成 `APPROVED/FROZEN`。
- 修改路径、版本或回执，使用户难以找到最后可信产物。

### 6.2 强制动作

1. 立即停止写入、删除、移动、合并、批准和冻结。
2. 将本轮可疑产物标记为 `QUARANTINED`；成熟度保持原状态或降为 `UNKNOWN`。
3. 记录事故编号、设备、路径、时间、受影响对话和文件。
4. 找到最后可信来源、版本和批准记录。
5. 对比事故前后差异。
6. 检查路径失效、上下文压缩、旧 Prompt、旧 Skill、局部旧规则和文件漂移。
7. 恢复最小可信链路并验证。
8. 请求用户批准退出事故模式。

### 6.3 退出条件

只有当来源、影响范围、恢复结果和后续预防措施均已记录，并且用户明确同意时，才能退出 C3。

## 7. 纠偏升级规则

- C1 一轮修复后仍出现跨模块漂移：升级 C2。
- 同一问题连续两轮未修好：至少升级一级。
- 任意等级发现虚构来源或权限越界：直接 C3。
- C2 期间无法找到可信基线：升级 C3。
- 不允许在同一轮中从 C3 自行降回正常模式。

## 8. HTML 五道门禁

## 8.1 Gate H0：开工门禁

开始生成 HTML 前，必须声明：

- 当前角色和任务。
- 输出是设计稿、可运行实现、分析报告还是笔记页面。
- 项目正本、设计基线和版本。
- 实际读取的来源文件。
- 允许探索和禁止改变项。
- 目标页面、模块、状态和断点。
- 文件落位计划与唯一正本候选。

无法读取基线时停止定义艺术方向。

## 8.2 Gate H1：骨架门禁

在完整编码前，先列覆盖表：

```yaml
pages:
  - page_id:
    purpose:
    sections: []
    states: []
    responsive_modes: []
    shared_components: []
    evidence_source:
```

长页面必须把首屏、中段和尾部分开登记；“后面与前面类似”不能代替具体模块。

## 8.3 Gate H2：设计系统门禁

集中管理并实际复用：字体、颜色、间距、内容宽度、圆角、边框、阴影、纹理、图标、动效和组件状态。重复模块使用同一组件或同一规则，不允许尾部临时复制一份近似 CSS。

对新增设计必须区分：

- `INHERITED`：直接沿用冻结规则。
- `ADAPTED`：为当前内容适配，但不改整体方向。
- `EXPLORE`：新探索，尚未批准。
- `EXCEPTION`：有证据的例外，需说明原因。

## 8.4 Gate H3：完整度门禁

逐页面、逐模块检查：

- 内容是否完整、准确并有来源。
- 信息层级和内容密度是否与基线一致。
- 首屏、中段和尾部的排版投入是否同等级。
- 空状态、加载状态、错误状态、长文本和极端数据是否处理。
- 图表、插图、图标和占位内容是否真实可用。
- 重复组件是否出现结构或样式分叉。

任何缺项都必须明确标记，不能用“整体完成”覆盖。

## 8.5 Gate H4：渲染门禁

平台能力允许时必须实际打开或渲染，不只阅读源码。最低检查：

1. 桌面宽度。
2. 移动宽度。
3. 关键项目增加一个中间宽度。
4. 所有目标页面或长页面全部区段。
5. 字体、图片、链接、滚动、溢出和交互状态。

只检查一张精选截图不算通过。未渲染的状态只能是 `UNVERIFIED`。

## 9. “前好后差”的专项检查

AI 容易把注意力集中在开头，再用重复卡片、默认组件或简化版式完成后半段。为此必须检查：

- 首屏与尾部是否使用相同的 Token 和网格。
- 每个后半段模块是否有明确目的，而不是为了填满页面。
- 后半段标题、正文、间距、图像和交互是否仍有完整层级。
- 重复模块是否真正复用，而不是视觉相似但代码和状态分叉。
- 是否出现突然变密、突然变空、突然换风格或全部卡片化。
- 是否只展示最漂亮的一屏作为整页完成证据。

发现两项以上时默认使用 C2，而不是逐条微调。

## 10. 四类角色合同

### 10.1 设计对话

负责艺术方向执行、页面和组件候选。必须引用设计基线；可以探索，但不能自我批准、解除冻结或覆盖整体方向。

### 10.2 主对话

负责把已批准的内容和设计落实为可运行产物。可以决定实现结构；不能因为开发方便而重写已批准设计，也不能把“代码完成”报告成“视觉批准”。

### 10.3 顾问对话

负责分析、风险、方案比较和汇报结构。HTML 是分析载体，不是事实来源。必须区分已确认事实、判断、建议和未知项；不能把建议渲染得像已批准结论。

### 10.4 笔记对话

负责信息整理、索引、阅读结构和知识链接。可以改善可读性；不能为了视觉完整而补写事实、来源或结论，也不能让样式压过检索和长期维护。

## 11. HTML 质量回执

执行对话必须使用 `templates/HTML输出质量回执.yaml`，至少报告：读取来源、基线、覆盖范围、设计规则、实际渲染范围、逐模块结果、偏差、未验证项、文件路径和建议状态。

设计自检可以由原对话执行；最终艺术批准仍属于用户或被明确授权的角色。

## 12. 用户如何选择纠偏等级

- 只有一个明确小问题，而且基线没丢：C1。
- 多个区域不像同一套设计，或者后半段明显偷工：C2。
- AI 说不清来源、虚构读取、越权改动或擅自宣布完成：C3。
- 判断不清时先发“一分钟诊断”，不要直接让它继续改。

桌面可直接复制版本位于：

- `launchers/AI跑偏时-三级纠偏提示词.txt`
- `launchers/HTML输出任务-开工与验收提示词.txt`
