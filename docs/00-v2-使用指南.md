# 个人 AI 治理框架 v2.2 使用指南

## 先知道哪份文件给谁

| 对象 | 开工先给 | 按需再给 | 不要默认给 |
|---|---|---|---|
| 总管 AI | 治理内核、用户 Profile、当前机器 Profile | 项目 adapter、冲突记录、来源登记 | 所有项目的完整聊天历史 |
| 项目管理角色 | 项目唯一正本、对应 adapter、当前状态 | 任务包、决策记录、汇报门禁 | 其他项目的内部资料 |
| 编码、设计或研究角色 | 开工声明、项目正本、当前任务、必要基线 | 对应专业 Skill 和模板 | 全域手册全集 |
| 临时对话 | 一份完整任务包和必要附件 | 标准回执 | 长期治理权和无关项目材料 |
| 新电脑上的首次总管 | 首次发现启动器和便携包 | 机器 Profile 模板 | 旧机器实例原样照抄 |

## 七层内容怎样组合

1. `core/01-governance-charter-v2.md`：所有电脑和项目共用的硬规则。
2. `profiles/user/user-profile.template.md`：用户长期工作方式和偏好。
3. `profiles/machines/`：当前电脑实际路径、平台能力和项目绑定。
4. `project_bindings[project_id]`：当前电脑上的项目根与发现证据。
5. `projects/instances/<project_id>.adapter.yaml`：项目稳定身份、正本相对位置、角色和门禁。
6. 项目仓库自己的唯一规则文件：项目事实与项目专属约束。
7. 当前角色、任务 Spec、设计基线和必要 Skill。

顺序越往后越具体，低层不能覆盖高层。任何一层不可达都要明确标记，不得靠聊天记忆补齐。

## 新电脑：发现、绑定、验证、治理

1. 解压当前便携包或取得治理仓库，确认 `governance_root`。
2. 把 `launchers/新电脑-首次发现-v2.txt` 发给新建的总管 AI。
3. 在用户授权目录内只读发现项目、Git 远端、规则文件、平台能力和知识库位置。
4. 用 `profiles/machines/machine-profile.template.yaml` 创建当前设备自己的机器 Profile。
5. 用稳定 `project_id` 匹配 `projects/instances/` 中的个人项目实例；不得沿用旧机器绝对路径。
6. 将本机项目根和证据写入当前设备的 `project_bindings`。
7. 实际读取项目正本，依次完成 `DISCOVERED → BOUND → VERIFIED → GOVERNED`。

无法验证的路径、角色或能力保持 `UNKNOWN/UNVERIFIED`。没有用户授权时不得批量修改已发现项目。

## 新项目：从通用协议创建实例

使用 `launchers/项目接入与本机绑定-v2.2.txt`。从 `projects/project-adapter.template.yaml` 创建一个以稳定 ASCII `project_id` 命名的 adapter，并把它保存到 `projects/instances/`。adapter 不保存任何电脑的绝对项目根；路径只属于机器 Profile。

项目已有宪章、规则文件或设计正本时，只登记来源并引用，不复制成治理框架里的第二正本。

## 日常任务：先声明，再连续完成

把 `launchers/总管AI-日常启动-v2.txt` 发给总管；专业对话使用 `templates/开工声明卡-v2.md`。AI 先确认项目、角色、已读正本、路径、所有权、输出位置、任务规模、验证和批准人。

低风险、可回滚且在授权范围内的工作，可以报告计划后连续完成。删除、覆盖、结构迁移、公开发布、硬权限修改和历史改写仍经过相应门禁。

## 设计与 HTML

设计任务开工必须同时读取当前设计基线和构图、排版方法 Skill。缺少任一项时只能探索，不能覆盖批准稿或冻结稿。

普通汇报默认 Markdown。只有设计对照、关系树、权责矩阵和依赖流程等确实需要可视化时才使用 HTML。HTML 要通过骨架、设计系统、完整度、前后质量一致性和真实渲染检查。

## 对话跑偏

- 局部错误、事实链仍可信：`C1 CORRECT-IN-PLACE`。
- 基线或方向漂移：`C2 BASELINE-RESET`。
- 大面积互相矛盾、来源不可达、越界或正本可能受损：使用事故恢复启动器，进入 `C3 INCIDENT-READ-ONLY`。

事故期减少写入面，不新增一堆 Prompt、文档副本或对话来掩盖冲突。

## 文件落在哪里

正式源文件进入项目原生结构或明确的对话工作区。每次批量生成前先给文件落位声明：`output_root`、可改和禁改范围、正本产物、临时产物、Review 位置、备份和清理策略。

桌面默认只保留一个当前自包含 ZIP。回执、反馈和审查记录进入项目约定目录；逐页 PNG 和联系表只进入可清理的临时渲染目录，不进入 GitHub、Obsidian、桌面交付区或 ZIP。

## 正本、镜像和发布物

- 工程正本：Git 仓库中的通用规则、模板、实例指针和构建脚本。
- 项目正本：各项目仓库自己的事实、规则和设计基线。
- 阅读镜像：Obsidian；只从工程正本同步，不独立修改。
- 发布物：完整 PDF、可编辑 DOCX 和单一便携 ZIP；需要修改时回工程正本重建。
- 个人实例：随用户迁移，但在每台电脑重新绑定本机路径。

## 当前状态

v2.2 已由用户批准，治理状态为 `APPROVED`。批准的是七条根本原则、项目中立架构和跨电脑续用规则；具体项目是否进入 `GOVERNED` 仍由用户按项目授权。
