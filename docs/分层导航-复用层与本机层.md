# 分层导航 · Personal Overlay Contract

> 本仓库 = **Kernel(通用方法)**。你的一切个人内容 —— 机器路径、身份、项目绑定、记忆、私有 skill ——
> 在**你自己的私有 Overlay 仓**里。两层分开维护,**而且个性化不需要你改动本 Kernel 的任何文件**。

## 一个万能测试

遇到任何一条,问:**「这条,拿到另一台电脑还成立吗?」**
- 还成立 → Kernel(在本框架里,换机不改)
- 不成立、要重查 → Overlay(去你的私有仓填)

## Kernel 怎么找到你的 Overlay

按顺序解析,**取第一个命中的**:

1. 环境变量 `GOV_OVERLAY` 指向的目录;
2. 本框架同级目录下任一含 `overlay.yaml` 的兄弟目录;
3. 都没有 → **只用 Kernel 自带的模板/默认值跑**,并在开工声明里写明「running on kernel defaults, no overlay」。

第 3 种是允许的:没有 Overlay 时框架照样能用,只是它不认识你。**绝不要为了个性化去改 Kernel 里的文件** ——
那样下次更新框架就会覆盖掉你,或者逼你手工合并。

## 槽位表(Overlay 提供什么,Kernel 兜底什么)

| 槽位 | Overlay 里的位置(建议) | Kernel 兜底 |
|---|---|---|
| `overlay_root` | 你私有仓的根 | 无(没有就走 kernel defaults) |
| `user_profile` | `profiles/user/<你>.md` | `profiles/user/user-profile.template.md` |
| `runtime_user_profile` | `runtime/02-user-runtime-profile.md`(你的实例) | 同名**模板**,只是形状示例 |
| `machine_instances` | `profiles/machines/instances/` | `profiles/machines/` 模板 |
| `project_bindings` | `projects/instances/*.adapter.yaml` | `projects/project-adapter.template.yaml` |
| `memory` | `memory/`(索引 + 原子档) | 无 |
| `personal_skills` | `skills/` | Kernel 自带的通用 skill |
| `harness_desired_state` | `harness/`(agent 配置的**源**) | 无 |
| `global_inbox` | 你私有仓根的 `INBOX.md` | 无(模板里写 `<GLOBAL_INBOX>`) |
| `capability_bindings` | 你的 adapter:搜索 / 抓取 / 浏览器 / 模型选择 | Kernel 只定义**能力名**,不绑实现 |

**解析规则一句话**:`Kernel 提供默认值与模板 → Overlay 覆盖 → 覆盖后的值才是本次任务生效的值`。
同名文件 Overlay 全胜;Overlay 没给的,用 Kernel 的默认值。

## 能力槽(只定义名字,不在 Kernel 里实现)

`spawn` · `message` · `wait` · `isolate` · `search` · `fetch` · `browser` · `validate` · `promote`

Kernel 只认识这些**名字**和它们的契约。具体用哪个模型、哪个爬取工具、哪套 multi-agent 原语,
全部由 adapter 或 Overlay 绑定。**别把某个具体产品写进 Kernel。**

换电脑:带走 Kernel,重填 Overlay 里的本机事实,永不把本机盘符/身份写进 Kernel。
